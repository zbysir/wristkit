# 像素猫怎么画

手环上的「Agent 猫」、App 窗口里的猫、菜单栏图标，都来自同一套像素帧，由 `pet-app/tools/gen_pet.py` 生成。这份文档记录这套猫是怎么画的、为什么这么画，以及改它的时候该怎么做。

## 结论先说

**猫要逐个像素手绘成一张字符格子图，不要用几何图形去拼。**

最早的版本用代码画椭圆、多边形、矩形拼出猫，再靠调坐标修细节，改了很多轮：身体要么像盒子、要么像团子，加脚像八爪鱼，肚子会从轮廓里鼓出来。几何图形在 40×40 这么小的画布上控制不住每个像素，越修越怪。改成手绘格子图之后，每个像素是什么颜色都写死，轮廓、脚、肚子都能精确控制。

几何版本里画得好的部分（头）可以直接从它的帧里逐像素抠出来，放进格子图里继续用。现在的头就是这么来的。

## 画布和位置

- 画布 **40×40 格**，导出时按最近邻放大，保持像素颗粒感。App 菜单栏、连接向导用的放大 4 倍（160×160 像素）；手环上的直接按屏幕上显示的像素出（222×222，`.sprite` 的 140px 按 336/212 换算），每格 5 或 6 像素、左右对称。不能让手环自己缩放：它缩放时会插值，边缘多一圈过渡色，没描边的 Clawd 贴着黑底看着就糊。改了 `.sprite` 的大小，要跟着改 `gen_pet.py` 的 `BAND_PX`。
- 猫本身是一张 **28 列 × 28 行** 的格子图，放在画布 `(8, 10)` 处：上面留出地方放牌子、Z、彩纸，右边留出地方放尾巴和牌子的杆。
- 猫**左右对称**：第 `c` 列和第 `24-c` 列对应，中线是第 12 列（画布 x=20）。尾巴不在格子图里，另外画。

## 格子图里的字符

| 字符 | 含义 |
|---|---|
| `K` | 轮廓（深色描边） |
| `F` | 毛色 |
| `S` | 条纹（额头、脸颊、身体两侧） |
| `D` | 暗部（大腿底部的阴影） |
| `C` | 浅色（口鼻、围兜、爪子） |
| `P` | 粉色（鼻子、腮红、肉垫） |
| `E` | 眼睛 |
| `W` | 眼睛高光 |
| `.` | 透明 |

三种猫（橘猫、灰猫、白猫）共用同一张格子图，只换每个字符对应的颜色。白猫的毛色和浅色很接近，所以爪子、围兜这些地方要靠 `K` 轮廓分开，不能只靠颜色区分。

手环上还有第四个形象 **Clawd**（Claude Code 的吉祥物），不是猫，不用这张格子图，在 `gen_pet.py` 的 `draw_clawd` 里单独画：照 Claude Code 欢迎界面里的字符画放大，一块不描边的橙色方身子、两只竖条眼睛、左右小短手、四条短腿。表情只换眼睛，动作靠挪手（举牌、敲键盘、挥手）和整只上下跳。它只在手环上，Mac App 的菜单栏和连接向导里还是三只猫。

第五个形象 **边牧**（gerdr 的狗）也只在手环上，在 `gen_pet.py` 的 `COLLIE_HALF` 里单独画：正面坐着、带深色描边，和猫一样逐格手绘，左右对称只写左半边。配色照 gerdr 的 logo（蓝陨石色的毛、白色脸中线、白嘴白胸口、橙项圈）。比猫矮 3 行，画的时候往下挪 3 格，脚底和猫对齐；笔记本、牌子、Z、彩纸和猫共用。踩过的坑：

- **照 logo 放大**：logo 是一条侧面在跑的狗，只有 16×11 格，原样放大两倍后身子长、腿长、脖子直，像马。
- **趴着睡**：侧面趴着在这个尺寸下是一长条，看不出是狗。睡觉和猫一样坐着闭眼。
- **竖耳朵**：正面的竖耳朵像猫。让它一眼看着是狗的是垂下来的深色耳朵、白色长嘴巴配大黑鼻子、伸舌头。
- **身子大半是白**：两侧只剩一条蓝，像鲸鱼的鳍。身子要整块蓝毛，白的只有胸口往下收窄的一块。
- **画两条白前腿**：腿比脸还抢眼。只在底部正中间露两只小白爪。
- **尾巴顶上一大块白、竖着翘**：像鲸鱼尾巴。尾巴是往外、往上弯的一道细弧，只有尖上一格白。

## 正面坐姿的猫长什么样

参考了网上的像素猫（比如 [pixie.haus 上正面坐着的虎斑猫](https://pixie.haus/pixelart/557825/adorable-tabby-cat-seated-forward-pose)），正面坐着的猫有这几个特点：

1. **头**（第 0~17 行，21 格宽）：
   - 小耳朵，只有 3 行高，在头顶两角；耳朵内侧的斜线直接接到平的头顶。
   - 头两侧上下都往里收一点，看起来是圆的；额头三道纹，脸颊两道纹。
   - 眼睛偏下，眼睛下面是一大块白色口鼻，粉鼻子，`ω` 嘴。
2. **身体**（第 18~27 行，最宽 19 格）：比头窄。脖子和胸口窄，往下是两侧的大腿，底部是平的（坐在地上）。
3. **胸口一块浅色围兜**，往下收到两只前爪之间。
4. **两只前爪并排放在底部正中间**，平放，上沿一道轮廓线和身体分开，中间一道缝分开左右。
5. **尾巴从身体右下角斜着往上翘**：5 个 2×2 的方块，毛色和条纹交替，不描边，先画、压在身体后面（沿用最早那版的尾巴，比在格子图里画的带轮廓的尾巴好看）。

踩过的坑：

- 身体画成椭圆、脚放在两侧：那是「站着的小怪兽」，不是坐着的猫。
- 前腿用几条粗黑竖线分开：像桌子腿或者「穿了裤子」。
- 前爪、后脚、大腿线全画上：底下一排竖条，像八爪鱼。**底部只留两只前爪就够了。**
- 浅色肚子画到最底下一行：盖住了底部轮廓，看起来像肚子突出去。
- 爪子用和肚子一样的浅色又不描边：白猫、灰猫上看不见。
- **身体和头一样宽**：整只猫显胖。身体要比头窄一圈。
- **耳朵大、高**（5 行高）：不像猫。3 行高的小耳朵就够了。
- **头又宽又扁、两侧是直的**：看起来是方的。两侧上下各往里收一格就圆了。
- **两只耳朵中间的头顶拱起来**：突兀。头顶保持平的，耳朵内侧斜线直接接上去。
- **加后脚**：在两只前爪两边再加两只后脚，底部变成一排四个白块，又像八爪鱼；后脚往外露一格，底部比头宽，又显胖。只留两只前爪。
- **举手**：头宽身体窄，手臂往外伸怎么画都突兀（像从脸上长出来、像天线，从肩膀长出来又显得脖子宽），举在胸前像一副眼镜。所以庆祝不举手。

## 表情、动作、道具

都在基础格子图上做，不重画整只猫：

- **表情**：只替换眼睛和嘴巴的格子。
  - 眼睛：左眼第 6~8 列、右眼第 16~18 列，第 7~10 行；右眼照抄左眼（不镜像，高光都在左上）。
    - 平常：带高光的圆眼睛；吃惊（举牌）：更高的眼睛；干活：只剩下半截，像在低头看屏幕；庆祝：`^ ^`；睡觉：闭眼的一道线。
  - 嘴：第 12~14 行，第 11~13 列，在白色口鼻部里。平常是 `ω`；吃惊、庆祝时张嘴。
- **动作**：整张格子图上下平移（跳一下、呼吸起伏）；尾巴上半截左右挪一格（摇尾巴）。
- **道具**：牌子、Z、彩纸、笔记本是用代码画的简单图形，叠在猫上面。敲键盘的两只爪子也是叠在笔记本上沿。

四种状态对应的帧数和节奏：

| 状态 | 什么时候 | 帧数 | 一轮时长 | 样子 |
|---|---|---|---|---|
| alert | 有 agent 卡住 | 6 | 700ms | 吃惊、张嘴，举着感叹号牌子跳 |
| celebrate | 刚跑完一个（持续 8 秒） | 6 | 800ms | `^ ^`、张嘴，跳起来，头顶撒彩纸 |
| work | 有 agent 在跑 | 6 | 900ms | 低头看笔记本，两只爪子轮流敲键盘 |
| sleep | 都空闲 | 8 | 2400ms | 闭眼，呼吸起伏，冒 Z |

## 改猫的流程

1. **改格子图或表情**，先把输出指向临时目录，**不要直接覆盖** `pet-app/src/common/pet/`：
   `PET_OUT=/tmp/pet .venv/bin/python pet-app/tools/gen_pet.py`
2. **出预览图**：三种猫 × 几个关键帧放在一张图上，放大 2~3 倍，和改之前的并排对比；有动作的再出一张 GIF。
3. **自己先放大看一遍**：轮廓有没有断、左右对不对称、底部是不是平的、白猫上的细节看不看得见、道具有没有被画布裁掉或者撞到猫。
4. **给人确认**，确认了再生成到正式目录（不带 `PET_OUT` 再跑一次），然后：
   - 手环快应用（`pet-app/src/manifest.json`）的版本号加一，`make app` 重新打包（会把帧同步到 Mac App）；
   - 重新生成 README 用的 `docs/pet.gif`、`docs/skins.png`；
   - 菜单栏图标是从每个状态第一帧里裁猫头（`server/app/trayanim.go`），猫的位置变了要同步改裁剪区域；右上角的牌子和 Z 不能裁进去。

## 手环会按路径缓存图片

手环系统按图片路径缓存图片：快应用覆盖安装、甚至卸载重装之后，同一路径还是显示旧图，重启手环才会更新。

现在 Agent 猫的帧在 `server/apps/agent-cat/assets/<BAND_PX>/<皮肤>/` 下（以前按帧内容哈希分目录的做法随旧版快应用一起去掉了）。手环按路径缓存图片：形象改了之后，App 里会提示「更新」，但更新完手环上可能还是旧图，要重启一次手环，或者把帧换个目录名（同时改 `index.ux` 的 `FRAME_DIR`）。换了图的尺寸更要紧：手环还按原来的尺寸缩放新图，画得比框大、被框切掉（160 换成 222 时就是这样），所以目录名带着尺寸，尺寸一变路径就跟着变。Mac App 没有这个问题：它有自己的一套帧（`server/app/frontend/public/pet/<皮肤>/`，菜单栏图标和连接向导用），和手环上 Agent 猫的帧分开放，都由 `tools/gen_pet.py` 生成。
